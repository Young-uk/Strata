# Clean-shutdown disk sessions for the personal integration

`atomic_disk_session_dir` opts the server into saving a drained native foreground session at shutdown and restoring a compatible session before admission and summary scheduling. The native session identity and a Python deployment identity must match. Missing, incompatible or failed restores retain cold-start behavior; a failed transfer restarts the engine before serving.

Shutdown stops admission and HTTP handling and verifies that foreground, summary, rollback, recovery and scheduler ownership are idle before native SAVE. Each session uses a random private filename. A fsynced manifest is atomically published before obsolete files are removed; failed saves preserve the last published manifest. Directory permissions are 0700, files are 0600, and old plus new snapshots share a 4 GiB budget. This is a clean-shutdown checkpoint, not a periodic or crash-recovery guarantee. It saves the native writer's deepest checkpoint with the live state.

CPU tests cover identity rejection, missing/corrupt manifests, atomic publication, size bounds, failed saves and busy ownership. Actual shutdown and restart restored native disk state in the personal Metal deployment. Restoring bytes does not prove reuse for a different request: native token and image prefix checks remain mandatory. Atomic Chat also canonicalizes tool-result object keys so Rust persistence does not change prompt bytes after app restart. A previously computed mixed-order KV state can require one new prompt read before normalized state is saved.
